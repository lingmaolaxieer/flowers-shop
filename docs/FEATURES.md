## 一、账号与权限（M1）

- 微信 code 登录（含 Mock）、手机号快速验证绑定、JWT 令牌与刷新
- 多身份切换：同一微信用户可在批发商/店家/顾客/配送员等身份间切换，切换后 scope 与权限实时变化
- 8 个预置角色：平台运营、批发商管理员/配货员/客服、店家店长/店员、顾客、配送员
- 20 个权限点，RBAC 守卫按角色控制商品/价格/库存/订单/财务/客服/打印/导出
- 店家入驻审核闭环：提交营业执照+手机号 → 人工核验 → 通过/驳回 → 自动发放店家身份
- 多租户强隔离：TenantGuard 从 JWT 生成 scope 并剥离客户端伪造的租户字段
- Web 内网测试登录（需替换为扫码授权）

## 二、商品与价格（M2）

- 商品 SPU：品种、等级、产地、规格、颜色、花期、图片/视频、预售/每日上新标记
- SKU 单位：扎/枝/束/箱；条码；顾客零售价（与批发价完全隔离）
- 四层价格体系：每日报价/时段价、店家等级价、一店一价、阶梯起批量价
- 取价优先级：一店一价 > 店家等级价 > 阶梯价 > 每日报价
- 报价单（订单内生成可改，改价权仅批发商）
- 批量商品导入（Web）
- **顾客端价格隔离**：顾客接口用白名单 VO，只返回 retailPrice，绝不含批发价/成本

## 三、库存（M2）

- 店家独立库存（A 店下单不影响 B 店）
- 库存锁定/解锁/扣减：悲观行锁 + 事务，防超卖（available 不为负）
- 超卖自动生成库存提醒（StockAlert）
- 损耗登记（只减库存，不自动回补）
- 库存调整、人工确认提醒（需人工操作，不自动补货）
- 库存流水日志（InventoryLog）全程可追溯

## 四、订单（M3）

- 两类订单状态机：顾客订单、店家订单，各自合法流转路径，非法流转被拒
- 顾客单：待确认→确认→待支付→已支付→（店家配送/自提 或 批发商接单→配货→出货→配送）→完成
- 店家单：待批发商确认（无时限）→确认→待支付→支付→配货→出货→配送/待自提→完成
- 超时自动取消：每分钟扫描超时待确认订单，事务二次校验后取消并释放库存锁
- 售后分支：退款中、部分退款、缺货替换、售后完成
- 订单留言、电话联系、微信客服入口
- 状态流转日志（OrderStatusLog）全程记录

## 五、二维码出货（M4）

- 一单位一码：编码 = 订单号 + 商品ID + 单位序号 + HMAC-SHA256 防伪签名
- 扫码防重：scan_records.code 唯一约束，重复扫码被拒
- 防伪校验：篡改任何字段或签名均被拒（timingSafeEqual 常量时间比较）
- 扫码记录批次/重量/损耗/配送人
- 离线扫码缓存 + 幂等同步（idempotencyKey 去重）
- 扫码记录导出数据源
- PrinterService 抽象 + Mock 实现；小程序端蓝牙 TSPL 指令封装（需真机调试）

## 六、支付与结算（M5）

- 微信支付 v3 抽象（PaymentService）+ Mock 实现；下单/回调/退款
- 回调验签 + 幂等（payment_callbacks 按 outTradeNo+eventType 去重）
- 退款路由：分账前从冻结资金退 / 分账后需接收方同意回退（180天窗口）/ 人工结算在对账单冲抵
- 抽成规则：订单金额比例、配送方式、花店、商品类目四维度，可配优先级与互斥组
- **30% 铁律**：分账模式抽成 >30% 强制拒绝并提示转人工；按金额分账；冻结期提示
- 逐花店结算勾选：微信分账模式 / 人工结算模式（后者不受 30% 限制）
- 配送费是否参与抽成：逐花店配置
- 分账记录、抽成明细（reporting 数据源）
- 发票状态记录（不接自动开票 API）

## 七、配送与通知（M6）

- 配送区域管理（基础费、满额免配门槛）
- 配送费计算：区域基础费 + 重量费 + 金额加价 − 满额减免
- 配送方式：同城、冷链、快递、自提、专送
- 快递/冷链人工录入运单号（不对接物流 API）
- 配送员状态更新 + 配送状态日志
- 预计送达时间（ETA）
- NotificationService 抽象 + Mock（订阅消息 + 语音提醒接口可替换）

## 八、营销 MVP（M7）

- 8 类活动：每日特价、节日预售（定金+尾款）、组合套餐、满减/优惠券、起批量优惠、会员价、积分
- 叠加/互斥/优先级通过规则 JSON 配置（不写死）
- 优惠试算（simulate）：展示生效与跳过的活动及原因
- 优惠券发放/核销、积分账户与流水
- 缺货替换价差处理（补付/退回由批发商售后确定，不自动处理库存）

## 九、对账与报表（M8）

- 周期对账单流程：系统生成 → 店家小程序确认 → 批发商 Web 审核 → Excel 导出
- 对账周期按花店配置（日/周/月）
- 8 类报表 + Excel 导出：
  1. 销量
  2. 库存损耗
  3. 抽成明细（订单号/金额/配送费/维度比例金额/分账或人工标识/抽成状态）
  4. 周期对账单
  5. 配送费明细（订单号/方式/区域/重量/金额加价/满额减免/实收/是否抽成）
  6. 退款明细（退款单号/原订单号/类型/金额/库存处理状态/分账回退状态）
  7. 商品动销
  8. 节日预售统计
- 审计日志、Webhook 订阅、幂等键、文件记录、定时任务状态表

## 十、前端

### 微信小程序（原生 TS，12 页面）
登录、身份切换、店家入驻、我的（聚合入口）、商品浏览、商品详情、购物车/下单、订单列表、订单详情、扫码出货（含蓝牙 TSPL 打印入口）、配送员端、店家对账单。
- 顾客侧页面严格只展示零售价，无任何批发价字段

### Web 管理端（Vue3，13 页面）
登录、店家审核、角色权限、批发商管理、商品管理、价格管理、库存管理、订单管理、抽成配置、配送管理、营销管理、报表导出、周期对账。

## 十一、二期（未实现，按约定另开对话）

拼团、秒杀、分销、多批发商入驻入口、规则引擎增强。

## 技术保障

- 金额统一整数分（BIGINT）存储
- 全量 TypeScript 类型检查通过（shared/api/admin）
- 每里程碑独立 migration + 等价裸 SQL，synchronize 关闭
- 所有业务表带 tenant_id/supplier_id/shop_id
- 不可实现项全部抽象为可替换 Provider + Mock 实现
