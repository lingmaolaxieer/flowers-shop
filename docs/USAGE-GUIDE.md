# 使用规范与操作手册

> 面向系统使用者：批发商、店家、配货员、配送员、顾客、平台运营。
> 系统有两个入口：**微信小程序**（日常业务）+ **Web 管理端**（批发商主账号/平台运营批量操作与报表）。

---

## 一、角色与身份切换

同一微信用户可拥有多个身份。首次进入小程序需微信授权登录并绑定手机号。

1. 打开小程序 → 自动 code 登录 → 进入"我的"。
2. 在"身份切换"页选择要使用的身份：顾客 / 店家 / 配货员 / 配送员 / 批发商。
3. 切换身份后，可见功能与数据权限随之变化（接口按 JWT 中的身份 scope 强制隔离）。

**角色权限一览**

| 角色 | 小程序可做 | Web 端可做 |
|---|---|---|
| 批发商主账号 | 配货、扫码出货、配送、对账确认 | 商品/价格/库存批量导入、抽成配置、报表导出、对账审核、角色权限、多批发商审核 |
| 配货员 | 扫码出货、蓝牙打印标签、库存/损耗登记 | — |
| 客服 | 订单查询、售后处理、订单留言 | — |
| 店家主账号/店员 | 下单、确认收货、对账确认、订单留言 | — |
| 顾客 | 浏览商品（仅零售价）、注册后下单、查订单 | — |
| 配送员 | 查看待配送订单、更新配送状态 | — |
| 平台运营 | — | 批发商入驻审核、全局配置、角色权限 |

## 二、店家入驻流程

1. 店家在小程序"店家入驻"提交：营业执照号、营业执照照片、联系电话。
2. 状态变为"待审核"，此时可浏览但不可下单。
3. 批发商主账号在 **Web 管理端 → 店家审核** 核验营业执照真实性（**需人工判断**）后通过/驳回。
4. 通过后系统自动为该微信用户发放"店家主账号"身份，可切换并使用店家功能。

---

## 三、顾客下单流程

1. 浏览商品（**只展示零售价，无任何批发价信息**）。
2. 未注册可浏览，下单前必须完成微信登录 + 手机号绑定。
3. 选花店 → 选商品与数量 → 加入购物车。
4. 购物车页试算配送费（区域基础费 + 重量费 + 金额加价，满额免配送费）。
5. 提交订单 → 状态"待店家确认" → 店家确认 → 待支付 → 微信支付 → 后续配货配送。
6. 订单内可留言、点击电话联系、接入微信客服。

> 店家若在 `ORDER_CONFIRM_TIMEOUT_MINUTES`（默认 30 分钟）内未确认，订单自动取消并释放库存。

---

## 四、店家下单流程（批发）

1. 切换为店家身份 → 查看今日报价（店家等级价/一店一价/阶梯价自动生效）。
2. 选商品下单（批发价可见，顾客不可见）→ 待批发商确认（无时限）。
3. 批发商确认 → 待支付 → 微信支付 → 配货 → 出货 → 配送/自提 → 完成。

---

## 五、配货员扫码出货流程（M4）

1. 配货员登录小程序 → "扫码出货"。
2. 点击扫码，扫描每件商品上的二维码（编码 = 订单号+商品ID+单位序号+防伪签名）。
3. 系统校验：防伪签名是否正确 → 是否重复扫码 → 通过后记录批次/重量/损耗/配送人。
4. 重复扫码或篡改二维码会被拒绝并提示。
5. 点击"打印标签"通过蓝牙连接 TSPL 便携打印机打印（**需真机调试**）。
6. 无网络时可离线扫码，数据本地缓存，联网后"离线同步"幂等上传（重复同步不会产生重复记录）。

---

## 六、配送流程（M6）

1. 同城/专送：配送员在小程序查看"配送中"订单，送达后更新状态为已完成。
2. 快递/冷链：批发商在 **Web 管理端 → 配送管理** 人工录入运单号（**不对接物流 API**）。
3. 自提：订单状态变为"待自提"，店家自提后完成。
4. 配送费按配置的区域/重量/金额规则自动计算，支持满额免配。
5. 订单状态变更通过微信订阅消息通知相关方；新订单触发语音提醒（Web 播报 + 小程序前台 + 配送员端）。

---

## 七、抽成与结算规则（M5，批发商在 Web 端操作）

1. **抽成规则**：按订单金额比例 / 配送方式 / 花店 / 商品类目配置，可设优先级与互斥组。
2. **逐花店结算方式**（二选一）：
   - **微信分账模式**：抽成 ≤ 订单金额 **30%**，只按金额分账，资金有冻结期。若配置的抽成 > 30%，系统**强制拒绝**并要求改用人工结算。
   - **人工结算模式**：资金先入批发商账户，按周期对账单线下结算，抽成不受 30% 限制。
3. **配送费是否参与抽成**：逐花店勾选。
4. **退款路由**：
   - 分账前：从冻结资金直接退；
   - 分账后：需分账接收方同意分账回退，受 180 天窗口限制（超时走人工）；
   - 人工结算：在周期对账单中冲抵。
5. **发票**：仅记录状态与信息（抬头/税号/发票号），不接自动开票 API。

---

## 八、营销活动配置（M7，批发商在 Web 端操作）

支持：每日特价、节日预售（定金+尾款）、组合套餐、满减/优惠券、起批量优惠、会员价、积分。
所有活动的**叠加、互斥、优先级**通过"营销规则"JSON 配置，不写死。用"优惠试算"预览叠加结果。
缺货替换产生的价差，由批发商在售后中决定补付或退回，系统不自动处理。

---

## 九、周期对账与报表（M8）

1. 对账周期（日/周/月）按花店配置。
2. 流程：系统生成对账单 → 店家在小程序确认 → 批发商在 Web 审核 → Web 导出 Excel。
3. 8 类报表均支持 Excel 导出：销量、库存损耗、抽成明细、周期对账单、配送费明细、退款明细、商品动销、节日预售统计。
4. 抽成明细/配送费明细/退款明细字段按需求完整提供（详见报表页列头）。

---

## 十、使用注意事项

- 涉及真伪判断的事项（营业执照、价格、损耗、缺货替换、运单号、发票、分账回退）均需**人工确认**，系统不自动决策。
- 顾客端与批发端价格完全隔离：任何顾客可见接口都不含批发价字段。
- 分账 30% 是监管红线，抽成超标一律走人工结算。
- 金额统一以"分"存储，界面展示时转为元。
- 生产环境务必修改 `.env` 中的密钥类配置；微信相关能力在未提供真实凭证前走 Mock，可正常走通流程但不产生真实资金/消息。
